# 用户视角验收条件与 ERBE 案例质量方法

_Owner: SGE governance | Version: 1.2.0 | Status: active | Updated: 2026-10-27_

## 适用边界与来源

- 编写或协作验收条件（AC）、Given–When–Then（给定情境、发生操作、可观察结果，简称 G-W-T）及 ERBE cases 时按需使用本方法。六点是撰写和复核视角，不是每张卡必须套用的六段格式；稳定背景可引用，关键可观察结果不可用“同上”省掉。
- 原始用户意图、原始 AC 与其批准 authority 决定范围及预期。本方法不改变 [ERBE canonical](../../data/strategy/strategy_erbe_specification_first_acceptance_v1.json) 的机器合同、判定、冻结或 RED/GREEN 权限，也不替代 [SGC canonical](../../data/strategy/strategy_sgc_structural_contract_v1.json) 的声明边界。
- KB JSON 保存稳定方法，生成 Markdown 是阅读投影；发现、待决、实际执行结果和 closeout 放 Dashboard。教学案例、清晰句式及结构检查均不是产品实现、产品验收或模型普遍质量提升的证据。

## 六项写法与复核问题

- 先说用户关心的事：先写真实操作者要做成什么，再补必要系统规则。复核：读者先能回答“我能完成什么”吗？内部流程应写真实 CLI 调用者、Reviewer 或服务消费者，不虚构终端用户。
- 具体例子贯穿：选一组有名字的输入贯穿 Given、When、Then 和 case 映射；边界另开 case。复核：输入、操作、预期是否同一情境？是否拿一个例子替代完整 AC 分母？
- 解释术语与影响的因果：首次使用术语时给短括注，说明保障缺失会怎样影响操作者。复核：术语是否解释了后果，而非堆叠实现名词？
- 区分用户结果与系统保障：Then 先写用户看见的结果，另写保障结果的状态不变量及其独立证据。复核：UI 标签相同是否被错当为字段身份、资源 ownership 或动态语义相同？内部日志不可冒充用户结果。
- 可观察行为：明确观察时点、输入值、输出/状态以及不得发生的副作用，替换“正常、正确、一致”。复核：另一位验证者能依据指定 oracle（预期判定来源）独立判定吗？
- 区分期望与现状：写明这是要求或教学期望；执行后另列实际结果、环境和证据。复核：未执行是否保留“未观察”，是否把 expected 写成已实现或通过？

## 贯穿教学正例与两层 G-W-T

### 教学前提与弱写法

以下 AC-DEMO-1 是明确假设的教学合同，不是 DataEase 事实：报表编辑者可将兼容目标中的“城市=北京、日期=最近7天”复制应用；城市条件和日期的动态相对含义均须保留，源页面不变。“最近7天”指以目标查询当日为锚点计算的相对日期，而非把复制当日算出的起止日期永久保存。真实产品的兼容性、日期口径、权限、持久化和异常政策须由原始合同指定。

弱写法：Given 系统正常，When 复制条件，Then 正确应用且状态一致。读者无法知道操作者、选择值、观察点或如何判断动态语义。

### 用户视角

- Given（假如）编辑者在页面甲选择“城市=北京、日期=最近7天”，页面乙存在合同规定的兼容筛选项
- When（当）编辑者复制并在页面乙粘贴应用
- Then（那么）页面乙显示这两个选择，查询使用目标查询当日的最近7天，页面甲选择不变。正式合同必须补查询日期口径、观察时点与结果 oracle；本示例没有真实产品 expected 数据。

### 系统视角

- Given（假如）复制输入在教学合同中包含 city=北京、date.mode=relative、date.value=last_7_days，目标映射兼容
- When（当）执行复制应用转换
- Then（那么）目标保留 city 和 relative/last_7_days 语义，源输入不被修改。动态语义保留使明天查询仍能按明天计算；只检查今天 UI 文案或今天结果不足以证明这一保障。上述字段仅是说明性记法，不新增 ERBE schema。

### 正例检查与执行状态

正例检查：同一“北京+最近7天”贯穿用户目标、操作、输出及系统不变量；用户结果以展示/查询证据判定，系统保障以状态/映射证据判定，二者分别指定 oracle。状态：教学期望；本任务未执行产品流程。

## 明确失败最小反例与待定边界

- 最小失败反例 DEMO-N1：保持教学正例中的城市、兼容映射、输入与源状态不变，仅把目标日期从 relative/last_7_days 转成复制当天固定起止日期。即使今天 UI 和结果相同，仍违反 AC-DEMO-1 明确要求的动态相对含义；教学 failure fingerprint 为 dynamic_semantics_lost。应对比语义状态或受控跨日查询，而非只看相同标签。此明确失败仅由上述教学 AC 支持，不声称是真实产品可信 RED。
- 边界 DEMO-B1/B2/B3：目标缺日期键、日期值为 undefined、日期对象为 {}，分别记录输入身份，不合并为一种空值。若原合同未规定它们是合法空选择、无效输入、默认值还是错误，则 expected 与 failure fingerprint 为待 oracle；指定 owner、补读来源并反馈主 Agent，不擅写“一律拒绝”。
- 不兼容目标、空选择及权限不足也须先查原 AC/合同：若已有处置则依其写反例；未定义就记录待决。环境、fixture、import 或路径错误是 execution error，不能伪装成行为失败或可信 RED。

## 原始 AC 到 ERBE 的可追溯链

- 原始 AC → 用户情境：保留 AC ID、精确源文件链接、原文范围、真实操作者、前置状态、操作、观察时点与可观察验收。另保留完整 Coverage Matrix；教学正反例不穷尽原分母。
- 用户情境 → 系统规则：由已批准合同映射 state_axes、terminal_predicates、invariants、forbidden_collapses。解释用户结果依赖哪条保障，不从漂亮句子推导新产品规则。
- 规则 → cases：正例固定输入/expected；最小反例只改变一个关键条件并给合同规定的 failure fingerprint 和禁止副作用；边界例覆盖相关边界并记录未知/冲突。各 case 绑定 oracle_owner、observable_evidence 与精确 authority 来源。
- 教学映射：AC-DEMO-1 → 编辑者复制北京+最近7天 → 城市与动态语义保留/源不变 → 正例 DEMO-P1、仅丢动态语义 DEMO-N1、缺键/undefined/{} 的 DEMO-B1..B3 → 教学合同可判 P1/N1，B1..B3 待正式 oracle。此链是人工内容映射，不是可执行 frozen ERBE package。
- cases → execution evidence：保留 case identity、环境、实际结果和可点击证据，分开 contract_verdict、execution_verdict、behavior。可信 RED 需合同有效、执行正常且符合预期 fingerprint；GREEN 复用同一 frozen identity，由独立 Validation 从 durable inputs 重算。
- 修改 → 权限边界：引用 write_exclusions、claim_ceiling。Builder 不得改 frozen Contract/Cases/expected/RED evidence/claim ceiling；确需改变时走 Contract Patch + Scope Delta + 必要人类批准 + re-RED，不以 G-W-T 文档取代。

## 主动发现隐藏需求与 Scope Delta 反馈

- 协作验收时应积极发现隐藏点并反馈主 Agent。先记录：发现 ID、原 AC/精确来源、触发情境、证据和未知、用户影响、推荐方案、scope/authority/expected/测试影响、owner、待决状态、下一步及批准 reference。反馈和候选不等于批准。
- 分类一“澄清”：现有 authority 已明确规定，补引用和解释；主 Agent 检查行为、分母、oracle 与 completion 未变后记录 disposition。分类二“新增”：原要求没有该能力，提出 Scope Delta candidate，说明增加范围与成本。分类三“冲突”：建议与已批准规则冲突，列双方来源及替换会丢失的范围。分类四“待决”：缺证据或 oracle，明确问题与 owner，不静默丢弃。
- 示例 F-DEMO-1：讨论复制应用时发现“保存后重开是否仍保留动态语义”。先查原 AC；已覆盖持久化则属于澄清并补相应 case；原 AC 只要求当前页面复制应用则属于新增 Scope Delta candidate，推荐补持久化要求及重开观察点，状态待主 Agent/适当 authority 决定。不得自行把保存重开写成已批准 expected。
- 示例 F-DEMO-2：发现应用中途失败时是否回滚所有条件。若无原 AC，反馈“建议原子回滚以免半应用”的新增候选，列失败注入和原状态证据需求；若合同允许部分成功，则记录冲突而非覆盖原规则。未有 oracle 时不产生可信 RED/GREEN。
- 主 Agent 对发现裁定：确认澄清、扩读、拒绝、defer 或请求批准。改变冻结要求、预期、oracle、authority、claim 或完成条件时使用现有 Contract Patch/Scope Delta/批准/re-RED 路线；Builder 不自行吸收。待决项留 Dashboard/open decision，可独立的非冲突范围继续；阻断当前案例 oracle 时标 blocked_oracle，并报告影响。

## 从具体仓库处境开始阅读进度

仓库owner接到映射任务时，先想知道它服务哪条原始AC；展开归属后，应找到场景、行为、共享关系与任务交付边界。看到方法页和模板都在时，还要能指出连接证据及独立验证尚缺什么；看完本次交付，应能用前后变化和证据讲清新增成果、剩余缺口和下一步。这些具体处境引出下面六项行为分解方法，不把教学例当产品现状。

## 行为分解一：四类对象与多对多关系

- 原始义务/AC、用户场景 G-W-T、系统行为 G-W-T、Session/任务是四类不同对象，各保留稳定 ID、精确来源、可观察验收判定及对应证据。义务按原始 AC/完成条件验收；用户场景按真实入口的可观察结果验收；系统行为按其合同、不变量及 oracle 验证；任务按其交付合同关闭。任务完成不推导系统行为通过，行为通过也不自动推导场景或原始义务满足。原始大义务可以保留最终整体验收边界，不为展示中间进度拆小承诺分母。
- 关系支持多对多，并保留关联 ID、两端对象 ID、关系含义及来源；主关联用于阅读组织，其他关联同样保留。树只是阅读投影，不能删去跨分支关联。教学例：B-DATE（动态日期语义）同时支持 SC-COPY（复制应用）和 SC-QUERY（目标查询）；T-MAP 同时推进 B-COPY 与 B-DATE。一个共享行为不被复制成两份实现，一个跨行为任务也不被误算成两个已验收场景。
- 权限、资源释放、独立审查等原始系统/流程义务可以直接关联系统行为或流程任务及其证据，无需经过用户场景层。保留真实 CLI 调用者、服务消费者、Reviewer 或无终端用户的流程对象，不虚构 UI 用户来凑齐层级。

## 行为分解二：连接状态与能力来源

- 关键依赖连接使用独立连接 ID，并记录源/目标对象、接口或交付约定、连接状态、责任人、证据及适用 revision。连接状态至少区分待接入、已接入未验证、连接验证通过、连接验证失败；证据不足时明确待核实。节点模块的状态与连接状态分开，不由模块通过推导连接通过。
- 教学例：B-COPY 和 B-QUERY 各自的模块验证通过，而 C-COPY-QUERY 的动态日期传递失败，则两个模块成果可见，连接记录失败，SC-COPY/SC-QUERY 的相应完整用户链仍未通过。连接证据应观察 relative/last_7_days 语义到目标查询的传递及按目标查询日求值，不能只引用两端测试或同一 UI 标签。此处是教学预期，不是产品执行事实。
- 能力来源分别标新增实现、已有能力复用、待核实，并列能力存在的来源证据与接线/调用验证证据。已有查询能力和拟复用点不等于已接通；来源为待核实时不猜成新增或复用。行为分解描述需要什么保障，不自动授权新增开发范围；实际实现范围仍由原 AC、设计与适当 authority 决定。

## 行为分解三：分层状态、验收入口与版本证据

- 按对象分别记录设计状态、实现状态、接入状态、测试准备、验证层级、验证结果、验证独立性、证据 revision 及当前有效性。测试准备包括 case/fixture/oracle/环境是否可用；准备完成不等于执行过。验证层级说明静态、单元、模块、连接、系统/场景或原始义务；独立性说明 producer 自检还是独立 Validation，不能合并成一个“已验证”。这些轴可并行、阻塞、回退，不是固定线性状态机。
- 未知表示没有足够证据确定状态；未开始表示有证据确认该项尚未启动；未运行表示已知该验证尚未执行；失败表示已执行且观察到不符合预期；环境阻塞表示环境或 fixture 等使行为无法判定。不得把未知填成未开始、未运行填成失败、环境错误填成行为失败；缺证据保留未知并列 owner、取证下一步。
- 历史通过保留原 revision、环境、范围、时间及来源。新版变更可能影响该证据时，当前有效性标受影响待复核，保留旧版通过而不自动升级当前状态；复核后再给出适用性与新证据。未证明当前影响范围时标待核实，不能仅因文件未变就猜为有效。
- 场景与义务验收按原始指定 UI/API/CLI/后台入口及 oracle 进行，不强制 UI；系统/流程义务可以没有终端用户。内部日志可以证明其对应保障层，但不能冒充用户结果。教学中“设计已独立审查、实现未开始”的对象应展示设计成果，父场景和原始义务仍未验收。

## 行为分解四：任务贡献与非单调进度

- 每次任务/里程碑贡献记录贡献 ID、任务 ID、关联对象 ID、变化前状态、变化后状态、具体成果及可点击证据、剩余验收缺口、下一步、owner 和适用 revision/时间。设计澄清、依赖确认、验证结果都是可见成果；前后变化仅对实际证明的状态轴生效，上层验收状态可以不变。尽量引用已有 Implementation Delta 或 Session 记录，避免平行维护同一变化。
- 允许零贡献（执行了工作但未推进既定对象）、发现新缺口、失败或回退。零贡献需说明观察和原因；新缺口关联发现 ID 与影响对象；回退保留旧证据、变更原因和当前待复核/失败状态。不得为显示正向进度覆盖历史或隐藏失败。
- 共享成果用同一贡献 ID 关联多个受益对象，不重复工作量或重复计数。用户视图可展示各场景受益，但不得相加成多个实现成果；不以任务数量、模块平均完成率或简单百分比自动升级原始义务。完成只能由原始验收谓词与相匹配证据决定。

## 行为分解五：隐藏需求、任务改路与稳定身份

- 发现隐藏需求后反馈主 Agent，保留发现 ID、原要求与精确来源、触发情境、证据/未知、用户影响、推荐方案、scope/预期/oracle/测试影响、owner、裁定及批准 reference。区分已有要求细化、实现任务调整和真正 Scope Delta；前两类在原要求、authority、预期与完成条件不变时记录后可继续，不默认每次都请求人类范围审批。
- 已有要求细化补充对象、关联或 case 映射；任务改路调整实现安排而保持原始验收分母。新增、删除、替换、延期原 must-have，或改变批准预期、oracle、authority、claim ceiling、完成条件才进入相应 Scope Delta/决策路线。冻结 Contract/Cases/expected 的修改仍按既有 Contract Patch + Scope Delta + 必要批准 + re-RED；Builder 不借分解调整自行改写。
- 保存重开两分支：原 AC 已包含持久化/重开保持动态语义，则补充已有义务的映射和 case；原 AC 未包含，则建立候选发现、说明影响并由主 Agent/适当 authority 裁定。候选与待决可见，但与已承诺对象隔离，不进入承诺完成统计，也不能通过删候选掩盖未决。
- 对象、连接、贡献和发现使用稳定 ID。细化、删除、拆分、合并、替换或重命名保留旧 ID、变更时间/原因、前后关系、源要求与裁定 reference；旧记录标明继承或失效关系而不静默消失。拆项不制造额外进度，未获批准的 Scope Delta 不改变原分母。

## 行为分解六：全过程使用、双视图与复用边界

- Goal/Design 建立原始义务、场景、行为、任务与关键连接的关联；任务卡下发只引用相关稳定 ID、AC pointer、输入输出和最大声明。里程碑/Session 收口更新各状态轴、任务贡献、证据适用性及剩余缺口；最终验收沿关联回到原始 AC/完成条件，并复核技术与流程 must-have，不以中间任务全部关闭替代原始验收。
- 用户视图呈现场景、阶段成果、障碍、下一步和本次推进；Agent 视图呈现系统行为、依赖连接、任务 owner、cases、证据 revision/有效性。双方由单份共享底表及其引用投影，使用相同快照时间/revision与证据来源；不分别手写状态真源，不复制全段 G-W-T。两视图不互为 truth，也不能用一视图遗漏的连接失败在另一视图宣称完成。
- 按比例记录：对象、关联、连接、贡献、发现是信息维度，不要求每个普通 Goal 建五张表；可合并为已有 OPCM、Session 或 Implementation Delta 的字段/区域，或引用既有权威记录。复杂依赖才按需分表；合并后仍能辨认对象身份、关联、证据、未知及前后变化，不能省掉原始必需信息。
- KB JSON 保持稳定方法，生成 Markdown 是阅读投影；skill 参考/recipe 提供执行入口；实际状态、贡献、发现、快照、blocker 与裁定留 Dashboard。引用复用现有 Original Plan Coverage Matrix、Session 和 Implementation Delta，不另建重复范围账本或状态真源。历史快照保留当时观察，当前表随证据更新；示例期望不能充当真实中间进度。
