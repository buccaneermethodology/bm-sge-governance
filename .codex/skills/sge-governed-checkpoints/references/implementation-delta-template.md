# 实现变更填写模板

本文是填写辅助，不能代替独立验收。按实际行为判断适用性；配置、脚本、schema、Provider 路由改变行为也适用。复制以下内容到实际 closeout 时替换所有占位，给出可点击的真实源链接；不要留下占位就宣布通过。

## 实现变更（Implementation Delta）

Implementation Delta: applicable（适用）。依据：〈具体行为变化〉。

按可独立解释和验证的变更项重复以下记录：

| 字段 | 本项内容 |
| --- | --- |
| 模块与前后行为 | 〈模块/区域〉；〈之前怎样、现在怎样〉；〈实际源文件 Markdown 链接〉。不能只列文件。 |
| 仓库与变更定位 | 〈仓库〉；〈已提交部分及提交链接〉；〈未提交部分〉；〈固定基线提交、快照、完整文件清单链接〉。混合状态分别说明。 |
| 验证证据 | 〈实际测试/运行收据/审查链接〉；〈结果及支持的行为和范围〉。分别注明通过、失败、未运行、缺失或失效，不推定通过。 |
| 原始目标影响 | 〈原 Goal must-have/AC 编号和来源链接〉；〈如何支持、尚不能证明什么〉。提交不等于达成。 |
| 未覆盖边界 | 〈剩余缺口、未验证场景、claim ceiling〉；无已知缺口时仍写明适用范围。 |
| 独立性与验收 | 〈提交记录、Builder 自检、测试结果各是什么〉；〈独立 reviewer/verdict 链接与边界，或明确“尚无独立验收”〉。表格完整不是通过。 |

## 固定验收对象

未提交/混合时提供基线提交加完整 tracked patch、untracked 原文与 manifest，或等价可重建快照；列全 tracked/untracked、新增/删除/重命名文件及内容。删除定位基线内容，重命名保留 old/new 路径及实际内容。只有路径/hash 或漏新增文件的 diff 不足。已提交与未提交部分分列，快照不是提交。

验收对象变化后：〈新快照或重新绑定说明〉；〈旧证据哪些仍适用、哪些失效、哪些需重跑/重审及实际结果〉。不能自动沿用旧通过。

## 多 Session 父面汇总

〈汇总各 Session 实际变化、对原目标的共同影响、剩余缺口和最终对象证据〉。可复用子 Session 证据链接，但不能仅列子 closeout。单 Session 写“不适用：本 Goal 只有一个 Session”。

## 纯文档替代段

仅在无代码行为变化时替换适用段：`Implementation Delta: not_applicable`（不适用）。依据：〈实际仅修改说明/导航，哪些行为均未改变〉。配置/脚本/schema/Provider 路由不能仅按扩展名豁免；其他治理审查、证据和独立验收义务仍按当前合同执行。

## 人工复核

按[人工清单](checklists.md#实现变更人工核验清单)和[正反例](implementation-delta-examples.md)核对。Reviewer 应能从正文说明变化、影响、缺口、声明上限，再点击真实来源。closeout 命令只打印提醒，closeout-language 不检查这六字段的真实性。
